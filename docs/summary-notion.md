# 时段摘要与 Notion 导出

本页说明现有实现契约。本次验证范围见 [1.1.16 更新说明](1.1.16更新说明.md)，复验使用合成消息与模拟 AI/Notion，不以旧结果代替本次验证。

## 使用方式

摘要时段使用左闭右开区间 `[开始时间, 结束时间)`：开始时刻的消息会计入，结束时刻的消息不会计入。结束时间旁的“此刻”按本机时间更新输入，精确到秒（`step=1`），并进行范围校验；不会自行生成摘要或设置定时任务。

“本地综述”无需配置服务、无需联网，提供消息及成员统计、逐段原话摘录和引用列表。它明确标记为摘录式综述，不宣称理解观点或推断待办。每个 `[M1]` 编号都映射到保存的消息 ID、群 ID、时间、原文；长消息会分片处理，引用仍回到同一条原文。若同步覆盖范围未知、不完整或不足以覆盖所选时段，会提示可能缺口。消息稀疏本身不被当作缺口证据。

“AI 摘要”由用户在独立“添加自定义模型”弹窗配置厂商、Key 和自由填写的模型 ID；OpenAI 排第一，预设地址只读并说明地域和套餐，自定义地址须明确输入。厂商或规范化后的实际请求地址变化须重新输入 Key，只有同一范围可保留旧 Key；旧无厂商配置按自定义保留。设置不自动测试或调用，详见 [AI 配置与错误排查](AI配置与错误排查.md) 和 [厂商官方来源](AI厂商API来源.md)。

在看清将发送的时段、条数、分段数和服务地址后主动确认调用。支持完整 `/chat/completions` 地址，也支持 `/v1` 基址；仅填写 HTTPS 服务根地址时使用 `/v1/chat/completions`。只允许 HTTPS；精确 `localhost`、`127.0.0.1`、`[::1]` 可以用 HTTP 连接本地模型。地址不得带账号、密码、查询参数或片段。Key 不写入摘要或日志，应由主进程受保护凭据存储保存。

1.1.5 在发送前校验协议，明确的 Responses、Messages 和旧 Completions 端点被本地拒绝。仅对精确官方来源 `https://api.openai.com`，将已知显示名 `GPT-6 Astra` 解析为同一 API ID `gpt-6-astra`，不改写用户原设置；官方请求使用 `max_completion_tokens: 4096` 且不带固定 `temperature`。1.1.7 对精确 Kimi 官方来源 `https://api.moonshot.cn` 和 `https://api.moonshot.ai` 省略固定 `temperature`，仍用 `max_tokens: 4096`；其他兼容服务保留自身模型标识与原 `temperature: 0.2`、`max_tokens: 4096` 方式，不套用 OpenAI 别名映射。

原生发送确认显示最终 URL、实际模型 ID 和每段 4,096 token 预算。官方预算包含推理与可见输出，不是字数、输入额度或总费用上限；多段分别请求。不因输出不足自动加预算、改模型或重试。设置例子与官方依据见 [AI 配置与错误排查](AI配置与错误排查.md)。

点击应用内确认发送后关闭该弹窗，主标题下的状态条继续展示等待原生确认、服务返回、成功或错误。生成期间禁用重复 AI 入口，失败保留错误状态且不自动重试；成功后由用户点击“查看摘要”，不自动跳离当前阅读位置。应用弹窗关闭不等于原生确认已通过；用户取消时不发送。

AI 按段串行调用，没有自动重试，避免未知失败导致重复计费。每段输入有固定上限，长消息完整分片；输出逐段保留，不做会丢失引用的二次压缩。若服务截断输出或返回工具调用，会停止而不是保存缺失的结果。不存在的消息引用会被替换并提示；无引用段落会提示人工核查。聊天在提示词中明确作为不可信资料，未给模型工具权限；这不能保证模型判断始终正确，仍应回查原文。

错误响应处理限 16 KiB 和 2 秒，只依据白名单代码和参数生成中文分类。原始 `message`、正文、响应头和可能回显的聊天/凭据不显示、不记入日志；安全分类不足时只提示通用 HTTP 状态。真实服务兼容性须由用户配置后主动确认验证。

## 删除本地摘要

每张摘要卡片右上角提供垃圾桶按钮。点击后显示应用内确认框，默认取消；确认后才删除当前账号、当前群中 ID 对应的摘要。摘要标题相同也不会误删另一份，删除结果保存在本机并在重启后生效。

取消不更改摘要；保存失败会保留摘要并提示错误。确认期间账号或目标内容发生变化时停止，不把旧确认用于新目标。删除仅更新摘要列表，不修改聊天、收藏、阅读位置或导出日志，不调用 AI、Notion，也不删除 Notion 中已经创建的页面。

## Notion

用户自行创建并配置 Notion 集成 Token，将所需目标页面共享给该集成，再主动读取可访问页面列表。应用只列出连接有权访问的页面，导出为所选页面下的新子页面。未授权的目标会由 Notion 拒绝。这里没有使用 Codex 或其他应用的密钥。

选择目标后可编辑导出标题与正文；核对后点击“确认导出”直接提交，不再额外勾选发送确认或弹出第二次确认。实际发送采用点击时的编辑快照，不回退到生成前的正文，也不改写本地原摘要或收藏。目标和字段校验仍保留，提交中禁用重复发送，失败保留提示，成功展示结果链接。预览不再自动插入覆盖核查提示段，本地摘要的缺口信息仍保留。默认勾选一个“引用原文与本地定位”复选框；它控制独立引用附录，切换保留编辑内容。取消勾选只去掉附录，不会自动删除用户正文或收藏正文中已有的原文。

附录包含原文、时间、成员及本地群/消息定位信息；这不是任何人都能访问的公开原文地址。确认导出意味着标题、编辑后的正文及启用的附录将发送到 Notion。内容按普通文本块发送，不把聊天中的 HTML、Markdown 或 URL 转成可执行内容或远程资源。文本与批次仍按上限拆分。

价值收藏可从单张卡片导出，或勾选 1–100 项后批量导出，支持“选择当前结果”，列表没有分页；空选不可导出。每次选择一份摘要或一组收藏，不混合两类来源。收藏正文从当前账号本地记录组成，包含备注、标签和所选消息；缺少对应原文时提示重新选择，不借其他账号补齐。目标选择后使用同一编辑器，导出不修改原收藏。

编辑契约将来源、目标、来源版本、编辑标题、正文与引用选项纳入导出识别。相同已完成编辑快照重复导出复用结果；修改标题、正文或引用选项会生成新导出键，并在用户确认后创建新页面，不覆盖旧页面。日志不保存 Token，仍须在每次写入前原子持久化，保存提交时的 `draft` 与 `sourceHash`，成功后记录已确认页面及进度。页面已创建但追加明确失败时，重开同来源/目标预览恢复原标题、正文和引用选项并提示续传；用户不必凭记忆重填，恢复也不自动提交。已确认成功批次不重发。

同来源同目标任一旧 `pending`/`uncertain`（含旧版日志）都阻断发送，恢复草稿不解除未知状态；唯一的 `partial` 或 `failed` 且有 `pageId`、有效草稿记录才自动恢复，预览的续传提示说明只继续原页面，修改续传稿被阻止。真实来源变化仍阻止旧稿续传，不把新来源混入已建页面。旧版部分日志没有 `draft` 时无法自动恢复，会提示核对目标页而不另建。旧 1.1.6 已完成日志不直接复用为新版编辑格式的结果，但旧不确定和部分日志仍拦截。

标题最多 180 字符、正文最多 200,000 字符，生成内容最多 2,000 块或 4 MiB。编辑快照保存在本地导出日志，不写回原收藏或原摘要；该草稿为明文，应按聊天资料保护，不含 Token，也不意味着未提交的任意输入都会自动保存。仅移除自动生成的覆盖/核查提示及 AI 来源中的核查字样；默认导出副本去掉已知的自动覆盖标题，原本地 `warning`、用户编辑和聊天原话不被盲目删除。

如果网络中断、超时、服务器错误或崩溃造成写入结果不确定，日志保持 `pending` 或 `uncertain`，后续点击会停止，避免重复创建或追加；更改编辑正文不用于绕过该停止。页面第一段包含 `微阅导出标识`，可在 Notion 目标页面中核对。如果服务器返回已提交页面 ID，也会保存在本地日志。此版本没有自动清除未知状态或自动对账界面；请保留日志并先人工核对目标页面，不能通过反复点击保证恢复。已成功导出的部分可能留在 Notion，应用不会擅自删除。

限流会遵守 `Retry-After` 并有重试上限；等待要求超过 60 秒时提示用户稍后再试，不提前重发。连接被明确封禁时停止重试。普通网络异常和 5xx 不会自动重试写操作。

## 主进程接口约定

`prepareSummary` 返回 `messages`（附 `ref`）、`chunks`（每项有 `index/text/refs/segments`）、`warning/range/title/groupId`。`localSummary` 和 `aiSummary` 返回合同规定的摘要对象，`refs` 附 `label` 与 `senderName`；编号与数组顺序稳定对应。

Notion 编辑接口以 `draft: {title,body,includeReferences}` 传递编辑内容，`includeReferences` 为布尔值；来源只允许当前账号的一份 `summaryId` 或一组 `bookmarkIds`。`NotionClient.exportSummary(summary,targetId,{journal,saveJournal,draft,sourceHash})` 的 `journal` 应传当前账号完整 `exports` 对象，`saveJournal(nextJournal)` 应原子持久化到同一账号。日志保留提交草稿、`sourceHash` 和来源元信息；恢复预览用 `resumeNotice` 提醒原页面续传。预览离线；发送前主进程重算来源，来源变化时停止，不发送旧快照。复验应覆盖临时 Store 落盘重启、编辑快照、取消零写入和原稿恢复，使用模拟远端；本轮实际结果见同次交付报告。

函数在成功持久化后更新传入日志对象，不得在保存回调里吞掉磁盘错误。主进程必须固定账号上下文，禁止把并行切换账号后的状态用于此次操作；凭据不能经 renderer 返回。AI 保持既有最终发送确认；Notion 的发送确认是预览中的“确认导出”按钮，主进程校验请求后直接提交。

## 验证与官方依据

单元测试位于 `tests/summary-notion.test.cjs`，运行 `node --test tests/summary-notion.test.cjs`。覆盖时段边界、超大字符串 ID、分段重建、引用、端点校验、AI 请求及错误、Notion 原子日志前置、幂等、失败续传、未知写入停止、限流和分页。测试全部使用内存模拟响应，不调用真实服务、不产生 API 费用。

2026-10-19 查阅 Notion 官方资料后固定 `Notion-Version: 2026-03-11`。页面搜索与版本依据：[Search by title](https://developers.notion.com/reference/post-search)、[Versioning](https://developers.notion.com/reference/versioning)。写入与分块依据：[Create a page](https://developers.notion.com/reference/post-page)、[Append block children](https://developers.notion.com/reference/patch-block-children)。大小、限流及未知写入处理依据：[Request limits](https://developers.notion.com/reference/request-limits)。

尚未验证：真实模型兼容性、真实 Token 的页面权限及 Notion 写入。需要用户配置自己的服务并明确确认一次实际操作后，才能完成这些联调。
