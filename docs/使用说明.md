# 微阅使用说明（1.1.21）

本版不自动升级日常安装。新增功能与边界见 [1.1.21 更新说明](1.1.21更新说明.md)，本地验收范围见 [测试说明](TESTING.md)，附件哈希以同批次 SHA256SUMS.txt 为准。

## 启动与工作区

将 portable ZIP 完整解压到当前 Windows 用户可写的目录，双击 `WeiYue.exe`。程序首次运行会创建虚构演示工作区；“打开演示”可以再次进入它。演示、导入和微博账号是分开的工作区，可在左侧账号选择器切换。

正式 portable 运行时，数据保存在 `WeiYue.exe` 同目录的 `data/`。源码运行时默认保存在源码目录的 `.local-data/`。界面提供当前数据位置；升级或迁移前，请先完全退出程序，再备份整个数据目录。跨 Windows 用户或设备复制后，受保护凭据可能无法解密，需要重新登录或配置。

不要将自己的 `data/`、导出文件或备份作为软件发布附件。详细边界见 [安全与隐私](安全与限制.md)。

## 登录微博与同步

1. 点击“官方登录”并打开官方登录页。
2. 在独立窗口的 `https://api.weibo.com/chat` 页面自行完成登录和必要验证。
3. 返回应用，点击“我已登录，读取群聊”，等待身份确认和群列表读取完成。
4. 在“选择我的群聊”中勾选需要保存在本机的群，保存选择。
5. 获取最近记录时使用最新同步；有离线积压时按钮显示“补齐离线消息”。“更早历史”只读取本地最早记录之前的数据，不用于补中段缺口。

已登录账号的已选群聊默认每 60 秒发起有预算的更新，可通过“暂停自动更新”停用，再按需恢复。补扫按群轮转、单并发连续分页，页请求间隔至少 1 秒，同时检查新消息。状态区显示实际补入数量及回溯位置，未衔接时重启会继续。遇身份、权限、风控或限流会暂停或等待，手动同步也遵守等待时间。取消选择群聊不会删除已保存记录。

便携版使用 EXE 同级 `data/`，新解压目录是独立数据位置。请固定一个日常目录；迁移应先退出并完整备份，不能直接用旧目录覆盖已有的新数据。

同步受账号权限、官方接口和历史可见范围限制。遇到验证或会话过期，请在官方页面处理；读取失败可保留会话重试，不要反复退出重登。没有继续翻到的历史、平台未返回的内容和已删除消息不会凭空补齐。

应用不发送群消息。设置中的“退出微博网页登录”移除当前账号的登录会话，保留已经保存的聊天、收藏和摘要。

## 阅读与搜索

消息按时间正序展示。分页控件放在阅读区底部，位于“加载到最新”和“最新已读位置”之间；中间栏移去重复标题，保留同步、筛选等业务操作。可手动翻页读取更早或更多内容。向下使用鼠标滚轮触底时自动追加一页，同一次连续滚动最多追加一页；在气泡外空白区域拖动到最底部时，松开左键后再追加一页，每次 160 条本地消息。关键词、成员和时间筛选继续生效，已显示的内容、选区和阅读锚点保留；自动追加不会把尚未看到的消息标为已读。后台刷新继续保留已追加的窗口，补入更早历史不会仅因列表序号移动而跳换内容。

已显示内容不足一屏时，向下滚动也可追加后续一页；没有后续本地消息时停止追加。切换群聊或筛选条件会重置追加范围，重新打开程序仍按已有的各群阅读位置恢复。自动追加失败后，可以再次向下滚动或点击“更多消息”重试。手动“更多消息”仍将当前窗口替换为已加载范围之后的一页；“更早一页”和“加载到最新”继续保留各自操作。触底翻页不跳到真正最新消息，也不发起网络同步或补扫。程序记住各群普通阅读位置，返回群聊或重启时恢复；新消息到达后显示“x 条未读”。

中间栏右下角“最新已读位置”回到本群最新读到的消息，并保留后面的未读。回看、筛选和程序跳转不会使已读进度后退，也不会提前读完未读。筛选妨碍定位时会自动清除并提示；本群尚无已读位置时按钮不可用。“加载到最新”是另一项显式操作，会跳到并读到操作时捕获的最后一条消息。

搜索框只搜索当前群已保存在本机的消息。打开“全部成员”，可按姓名或 ID 搜索并勾选多个成员；重名成员显示 ID。改变搜索词保留原来的勾选，“清除选择”恢复全部成员。多个勾选成员按任一匹配，与关键词、时间及重点成员条件同时生效。头像左侧的选择框和下方的收藏、重点图标默认隐藏。鼠标进入头像后显示，并可沿连续操作区移到按钮或选择框；键盘焦点进入同一区域时也显示。仅悬停消息正文不会显示这些控件，图标仍有操作名称和状态提示。设为重点后，成员昵称在框外加粗，默认重点昵称与正文使用深红色 `#860000`，消息内容区使用纯色浅粉 `#fcd3d4`，头像与昵称区域保持透明；取消重点回到当前普通消息配色。已读定位和选择状态保留独立外层标记，避免与气泡颜色混淆。重点按成员 ID 匹配，不按同名推测。

默认聊天区域采用浅灰底，普通消息正文在随内容收缩的白色气泡内显示，气泡有左上小尾角与轻阴影。头像与昵称在框外；长文本会换行，图片、附件和引用内容适应可用宽度，短消息不会强制铺满一行。价值收藏里的消息摘录沿用气泡样式；系统通知使用透明背景的小字紧凑显示，不使用消息框、边框、阴影或尾角；长通知仍可展开，文字根据深浅聊天背景保持清晰。重点消息默认使用浅粉气泡与深红正文，昵称仍在框外加粗，并按重点昵称颜色设置显示。

在气泡外空白区域按住鼠标左键并拖动，可以滚动阅读列表；从气泡内正文开始拖动仍是选择文字；气泡内边距、链接、图片、按钮和选择框不会触发拖滚，并保留各自操作。松开左键、指针离开窗口、窗口失去焦点或切换视图时停止拖动，拖动结束不会误触发点击。

只有官方返回的明确系统通知类型使用无消息框的小字紧凑行；背景透明，没有边框、阴影或气泡尾角。长通知点击展开可查看完整内容，再次点击可收起；文字自动适应深浅聊天背景，保持清晰。普通群成员消息不会因为群名或昵称包含“粉丝群”等文字就被折叠。

在“更多筛选”设置开始和结束的日期、小时、分钟，时间按北京时间（UTC+08:00）解释。开始包含该分钟第 0 秒，结束包含整个所选分钟。例如起止都填 18:42，会显示 18:42:00.000 至 18:42:59.999。结束早于开始时显示提示并保留上次查询结果，可修正或清除筛选。这里的阅读筛选与下文摘要的结束边界规则不同。

中文输入时正常完成组词，组合结束后会延迟查询；普通 Enter 可立即查询。筛选视图不覆盖普通阅读位置，清除筛选会恢复原位置。若要反馈输入法问题，请提供 Windows 版本、输入法名称和不含真实聊天的复现步骤。

不同成员消息之间采用较紧凑的纵向间距，昵称和时间仍保留。群聊图片可点击查看原图；分享微博可能只包含已取得的部分信息。“我发布了新微博，快来围观吧”这种未提供原帖信息的纯通知仍按通知显示，不推测或抓取某条原帖。

消息中的 HTTP / HTTPS 网页地址点击后交给系统默认浏览器打开，不额外弹出确认框；不会在聊天界面直接执行网页代码。HTTP 地址没有 HTTPS 的传输保护，请核对目标后再点击。普通文字、HTML 片段和其他协议不会获得应用操作权限。

## 气泡布局与颜色设置

本轮减少气泡周围的多余空隙，保留原有文字字号和媒体可用尺寸。气泡随实际文本或媒体内容调整大小，不承诺所有短句具有同一高度。

在设置中分别调整以下六项颜色：

| 项目 | 默认颜色 |
| --- | --- |
| 聊天背景 | `#f1f3f2` |
| 普通成员昵称 | `#52634b` |
| 重点成员昵称 | `#860000` |
| 普通消息气泡 | `#ffffff` |
| 重点消息气泡 | `#fcd3d4` |
| 重点消息正文 | `#860000` |

每项可通过颜色选择器或 HEX 文本输入独立调整。HEX 只接受 `#RGB` 或 `#RRGGBB`，不接受透明度、颜色名称或其他 CSS 表达式；无效输入需要先修正才能保存。

局部预览使用合成消息，不需要读取或改变真实聊天。点击保存后只保存到当前账号；其他账号保持各自设置。取消会返回设置页，不保存本次编辑。“恢复默认”只将当前草稿改成上表默认色，仍需保存才会生效，取消不会应用默认色。

普通正文及选择自动模式的重点正文会根据气泡背景保持至少 4.5:1 的对比，链接继续自动保持可读性。重点正文也可显式选色：低对比时只提示，不悄悄改写所选颜色，因此显式颜色不保证 4.5:1。昵称同样保留你选择的颜色，仅在低对比时提示。系统通知没有消息框，其小字颜色自动适应聊天背景。

已有五项自定义颜色会原样保留；旧配置没有重点正文颜色时，该项使用自动对比。尚未配置外观的账号和执行“恢复默认”的草稿使用上表六项新默认色，不会把旧自定义配色直接替换为新默认。

## 微博表情

本版共 409 个映射、408 份官方原图，保留已核验的官方紫底“空”图标 `[/ee88ab.png]`。保留已有官方名称、公开目录、聊天默认选择器和旧路径映射，来源见下方表情说明。支持方括号 `[名称]`、全角 `【名称】`；包括已有的“苦涩、流鼻血、老师好、卡皮巴拉、泪奔、无聊、666、淡淡的、送花花、拜托、努力、捂嘴哭、手指比心、呵呵、流汗、融化”，及 `[/ee8192.png]`、`[/ee88a6.png]`、`[/ee84a5.png]` 等既有路径和新增 `[/ee88ab.png]`。共支持九个已确认的旧路径，不添加猜测的 `[空]` 别名。

资源从本地加载，固定内联尺寸；失败时回退原始代码。未知名称、未知路径、普通括号文字与 URL 中片段不替换。当前收录均为 PNG 静态图，未核实的专属、付费、自定义或动态表情不承诺覆盖。

复制、搜索、收藏、导出及摘要保留原代码和括号；表情不会作为聊天图片发送 AI。来源和逐项验证信息见 [微博表情说明](WEIBO-EMOTICONS.md)。

## 引用图片和微博

消息真实返回引用微博、转发原帖或关联微博结构时，界面分别展示已取得的正文、配图与“打开被引用的微博”入口。图片使用与普通图片相同的受限查看器，微博链接通过默认浏览器打开。加载失败、删除或不完整时保留提示，不把缓存伪称为当前完整原帖。

有些聊天引用只保存了“「图片」”文字，没有稳定原消息 ID 或原图地址。对于可补全的旧记录，程序进行一次受限信息补全；官方详情和目标列表仍缺少原图信息时，显示“网页版未提供原图信息”。已核查的这类真实引用仍不能打开原图，不会根据昵称、相似文字或邻近消息猜测配图。纯“我发布了新微博”通知也不会被当作可确定的原帖。

## 群与成员头像

左侧群列表和消息旁会显示已取得的群头像或成员头像。程序按稳定的群 ID、成员 ID 对应头像，不通过相同昵称猜测身份，也不会把某位成员的头像当作群头像。

官方登录确认时会保存取得的群头像。升级后可先点击“同步最近”：手动同步会读取一次正常群列表，仅按已选群的稳定 ID 刷新目标群头像，不新增或保存其他群的资料。每 60 秒自动更新不会为头像增加群列表请求。

成员头像随消息同步或用户请求的消息补全取得，不额外遍历无关联系人，也不回扫全部历史。旧记录尚无头像、接口没有返回可校验字段、图片地址不在允许范围或图片加载失败时，仍显示原有的文字或颜色占位；并非每条历史记录都保证具有头像。

头像在固定大小的位置按需显示，更新头像不会重建整条消息、改变阅读锚点或将消息标记为已读。加载失败后短暂保留占位，约 60 秒后的界面刷新可再次尝试同一地址；已成功或正在加载的头像不会因普通刷新反复重建。头像与聊天附件分开处理，不加入摘要、AI 图片输入或分享微博正文。接口可能没有返回可显示头像；离线测试不保证每个实际群、成员或历史记录都有头像。

## 查看与保存图片

点击图片后，在独立的大图窗口中查看。窗口没有原生标题栏，顶部可拖动，并提供最小化、最大化或还原、关闭按钮；可调整窗口大小，也可以按 Esc 关闭。

- 使用滚轮或放大、缩小按钮查看细节，选择“适应窗口”或“原始大小”恢复相应比例。“适应窗口”会缩小超出窗口的图片，不强制放大小图。
- 放大后拖动图片平移查看；缩放和平移仅改变显示，不改写图片内容。
- 点击“另存为…”，在系统“将原图另存为”对话框中选择文件夹和文件名，再点击“保存原图”。程序保留取得的原始图片格式与字节；文件扩展名须匹配实际格式。取消对话框不会写入文件，覆盖同名文件需按系统提示确认。

查看和保存支持 JPEG、PNG、GIF、WebP，以及受支持的 HEIC 图片，原始文件单张上限 20 MiB。图片来源、重定向、体积和实际格式都要通过校验；加载失败或不支持时会提示，可点击“重新加载”或在官方页面查看。不能把一个失效地址或错误页面另存为图片。

部分聊天图片由服务端声明为 JPEG，实际字节却是 PNG。聊天图片入口在来源、体积和声明格式校验通过后，可按真实的 PNG、JPEG、GIF 或 WebP 签名纠正这类不一致，显示和另存为均使用实际格式，原图字节不变。HTML、SVG、未知格式或缺失格式声明仍会拒绝；此兼容规则不放宽头像或 AI 图片输入的格式校验。

有些图片虽然叫 `.jpg` 或由服务端声明为 JPEG，实际字节仍是 HEIC。程序按文件头识别这些图片，在本机独立沙箱中的解码任务转成 PNG 显示；不向第三方发送图片。点击“另存为”保存的仍是未经改写的原 HEIC 字节，默认使用 `.heic`，也允许 `.heif`；不会把 HEIC 原文件伪装保存成 `.jpg`。这不是“另存为 JPEG”或通用格式转换功能。

本地转换后的 PNG 上限为 64 MiB，解码另有像素、边长和超时限制。HEIC 支持不代表所有 HEIF 编码、AVIF、超大图或损坏文件都能解码。图片尺寸过大或解码失败时，应用保留明确错误状态，不显示虚构的成功预览。

接口明确提供多个图片字段时，程序校验后选择可用地址，不推测未提供的地址。若来源只提供预览图，取得的图片可能不是原始分辨率；“另存为”保留实际取得的图片字节，不把预览放大成原图。

图片按需读取并暂存内存，手动保存只保存当前所选图片，不构成完整离线媒体归档。另存为的文件不加密，请自行保护保存目录。

## PDF 文件和分享视频

已取得可用附件信息的消息会显示文件名或视频入口。打开附件后，在独立窗口操作：

- PDF 使用本机随附的 PDF.js 画布预览，提供页码、上一页/下一页和缩放控制。单份上限 50 MiB；不执行 PDF 活动脚本，也不保证表单、动画、嵌入文件等交互功能。
- 视频和实况照片在打开预览后自动播放，保留播放/暂停、进度、音量等播放器控制；消息列表不会自动播放。支持受允许来源的 MP4 / WebM 文件，单份上限 200 MiB；扩展名相符不保证编码一定可播。打开预览后，原生播放失败的短 HEVC 会自动在本机转换一次，只处理不超过 20 MiB、30 秒且尺寸等校验通过的文件。准备时提示“正在本机准备兼容预览…”，关闭窗口可取消。转换在本机隔离任务内完成，成功后自动开始播放，不改变原文件，也不上传至转码服务。失败后显示原因，不自动循环；你可以主动重试或保存原文件。
- “另存为”通过系统文件对话框保存已取得的原文件，保留实际格式及扩展名。取消不写入，覆盖同名文件按系统提示确认。

需要先成功取得实际附件字节，才能预览、播放或保存。来源链接缺失、过期、权限不足、平台拒绝、文件过大、损坏或编码不受支持时会显示具体失败状态；仅有“文件消息”“分享视频”文字不能凭空还原附件。不猜测下载地址，也不绕过平台验证。

PDF 和视频按需读取，不自动遍历全部群附件，不构成完整离线归档。查看附件不会将其提交给 AI 或 Notion。切换账号后，旧账号的查看窗口和未完成读取失效。保存的文件未加密，应自行保护。

## 实况照片与压缩文件

官方实况照片通常由静态图片和独立视频组成。消息有明确的实况视频关联时，图片仍可点击查看原图，另有“播放实况照片”按钮，打开后自动播放；可随时暂停或调整音量和进度。仅有静态图片或缺失视频字段时不推测视频地址。短 HEVC 的本机兼容预览遵循上面的 20 MiB、30 秒及尺寸限制；不支持或转换失败时显示具体原因。只要原文件已经取得并通过校验，仍可使用“另存为”保存原文件，转换后的预览不会替换它。

ZIP、RAR、7z 仅提供“下载压缩文件”。应用先验证账号、官方附件元数据、下载地址、体积、MIME 与实际文件签名，再打开系统保存对话框供你选择位置。上限 200 MiB；不解压、不运行，也不自动打开下载文件。取消对话框不写入；覆盖已有文件由系统正常确认。加密内容不会尝试解密，HTML、脚本或伪装格式不作为压缩文件保存。

## 本地消息回收区

1. 进入“设置与连接” → “管理本地消息与回收区”。只操作当前账号的数据。
2. 选择一个群，填写北京时间开始与结束分钟。“最旧”使用该群当前可见的最早消息所在分钟；“此刻”使用当前北京时间分钟。开始包括第 0 秒，结束覆盖该分钟全部 60 秒，起止倒置会提示。
3. 在成员列表中搜索并勾选需要保留的成员；选择以 ID 为准，重名可区分，改变搜索词不丢失勾选。没有勾选表示不额外按成员保留。
4. 按需保留已用于本地摘要或 AI 总结的完整时段。范围来自保存的摘要起止时间，不用零散引用的最早/最晚时间猜测范围。
5. 点击“预览筛选结果”，核对群、范围、命中数、保留原因、待回收数量与样例，再点击“确认移入回收区”。取消不会改变数据；预览后关联数据发生变化需要重新预览。
6. 从同一入口打开“本地回收区”，按批次恢复。恢复不推进阅读位置，也不把消息当作新到达消息处理。

收藏原文、摘要引用、导出关联、当前未读、阅读定位和同步锚点消息始终保留。历史摘要缺少可信范围、引用时间与范围矛盾，或导出记录无法追溯来源时会保守保护并显示原因；可能因此没有可回收消息。保留原因可以重叠，不能把各原因计数直接相加。

**这是可恢复的隐藏，不是磁盘清理。** 原始记录仍保存在当前账号数据中，正常阅读与新摘要会排除它们。同步、补扫和重新导入不会自动恢复回收消息，只能由明确的恢复操作重新显示。本轮不提供永久清空。收藏、摘要、凭据及已经导出的 Notion 页面不被删除；备份文件也不随回收操作改变。

**数据格式与回滚：** 第一次实际回收会把当前账号格式升为 2；仅打开候选、筛选或预览不会升级。即使恢复全部回收消息，格式仍为 2。1.1.16 及更早版本明确拒绝读取格式 2，不能用旧版直接打开新数据。首次回收前请正常退出并保留完整备份；需要降级时使用启用回收前的备份，并单独保存当前完整数据，因为旧备份不包含此后新增的消息、收藏或摘要。

## 收藏与导出

点击单条消息的“收藏”，或勾选多条消息，再在工具区添加备注和逗号分隔的标签，选择“保存到价值收藏”。

“价值收藏”中可以搜索正文、备注及标签，修改备注标签，或移除收藏。移除收藏不会删除原聊天记录。“回到原文”定位本地消息；原文不在本地时需补充同步或导入。

Markdown / JSON 导出包含当前搜索条件匹配的收藏、备注及原文。它们是普通未加密文件，保存或分享前请检查内容。收藏 JSON 是收藏导出格式，不是下文的群聊导入格式。

## 指定时段回顾

1. 选择群聊，在“按时段回顾”中填写本机本地时间。
2. 时间边界为“开始包含，结束不包含”。可使用“今天”“昨天”“近 7 天”，或点击“此刻”把结束时间设为当前秒。
3. 点击“检查时段与内容”，查看消息数、分段数和覆盖提示。“查看待处理内容”展示前 20 条预览，不代表只处理这 20 条。
4. 选择“生成本地摘录”，或在配置 AI 后选择“使用 AI 总结…”，等待待发送内容准备完成并核对范围。

本地摘录只统计和摘取聊天原话，不解释图片或额外补抓分享正文，不推断观点或待办，也不调用 AI。长记录按段处理，摘要会保留可回查引用。覆盖提示只能反映程序知道的同步与导入范围，不能保证平台端没有缺失内容。

生成结果自动保存在当前工作区的“时段摘要”中，可回查引用、导出 Markdown，或继续导出到 Notion。

每份摘要右上角的垃圾桶用于删除该份本地摘要。点击后先核对确认框，再选择删除；默认操作为取消。删除按摘要的固定 ID 定位，同名摘要不会一起删除，重启后仍保持删除结果。取消或保存出错时保留原摘要，并显示相应结果；确认失效或保存失败后需要重新打开删除确认。

删除只影响当前账号的这一份本地摘要，不删除聊天原文、收藏、阅读位置、其他账号资料或已经导出的 Notion 页面，也不调用 AI 或 Notion。确认前请核对目标；需要保留内容时可先导出或备份。

## 配置与调用 AI

在设置中打开模型配置，选择服务商或自定义服务，填写兼容 Chat Completions 的服务地址、自己的 API Key 和实际 API 模型 ID。预设地址是填写辅助，服务权限、模型可用性和计费由对应提供方决定。

AI 和 Notion 设置分别保存。已保存 Key 不回显；更换服务商或服务地址时需要按界面重新确认对应凭据。保存设置本身不会发出 AI 请求。

在“图片理解能力”中选择：

| 模式 | 含义 |
| --- | --- |
| 自动识别已知官方视觉模型 | 仅对程序识别的官方 OpenAI 视觉模型启用图像；未知服务或模型不会自动视为支持。 |
| 我确认此模型支持兼容协议的图片输入 | 由你确认所选服务及模型支持 Chat Completions 的 `image_url` 图像输入。保存此选择不会探测服务，也不保证服务端接受请求。 |
| 仅发送文本，不发送图片 | 图片会在发送前列为未包含项。 |

本版沿用 Chat Completions 兼容协议，不将原生 `/responses`、Anthropic `/messages` 或 Gemini 原生协议自动转换为另一种接口。不支持图像的服务或模型不会因为填写了一个图片 URL 就得到“已读取图片”的声明。

发起 AI 总结时：

1. 应用先固定所选群与时段的消息，在本机准备内容。需要补充普通分享微博时，沿用当前已登录且有权读取的微博会话；不请求额外账号权限，也不读取无关群聊。演示与导入工作区不会登录微博补抓正文。
2. 在“确认发送至 AI 服务”中核对实际服务地址、模型、聊天消息数、分享微博正文数、图片数及体积、重复图片数、分段数和遗漏条目。展开正文预览可查看前 20 条；实际处理数量以范围清单为准。不能把部分正文、失败图片或纯通知当成完整原帖。
3. 图像能力允许时，发送的是已取回的图片数据，而不是仅发送 URL 或图片数量。勾选“我已核对实际正文、图片与遗漏，确认发送并承担所选服务费用”，点击“确认发送并生成”，再在系统“确认发送内容”对话框中核对并选择“确认发送”。此后，所列聊天、成员显示名、时间、引用标记、分享正文和图片才会发给选定 AI 服务。图片可能增加 token 用量与费用。
4. 准备中点击“取消准备”或关闭发送预览不会发出 AI 请求。发送中的“取消请求”会尝试中止后续处理，但不能撤回服务已经收到的内容或保证不计费。失败后不会自动重试、改用新服务、调用额外 OCR 或切换模型；如需重试，先检查错误，再重新准备并确认发送。

准备的快照暂存内存，5 分钟后失效；切换账号、修改模型配置或使用过该快照后，需要重新准备。更换服务、地址或模型时，“图片理解能力”恢复自动识别，请重新核对。保存摘要会记录本次发送范围与遗漏，不保存所发送图片的数据副本。

为控制单次请求的体积，本版图像预算为单图最多 4 MiB、每次请求最多 4 图及 8 MiB、每次总结最多 24 张不同图片及 24 MiB，均按原始图片字节计。相同图片会去重；超过预算的条目在发送前明确显示为遗漏。每段生成上限为 4096 token，不会自动提高预算。

内容准备最多尝试补充 24 次分享微博或图片消息详情，正文与图片读取共用 90 秒预算，单次读取默认最多 10 秒。达到条数或时间预算、仍只取得部分正文时，会保留已有内容并注明未完整纳入的范围。这些限制不代表平台上的全部原帖或图片已可访问。

AI 图像输入当前限 JPEG、PNG、WebP。GIF 和 HEIC 虽可在图片窗口查看和保存，但不会因为本地可显示就自动转换并发送给模型；PDF 与视频也不作为模型附件发送。请核对发送前的范围与遗漏清单。不支持的格式、已删除或权限不可见的微博、失效图片、网络错误，以及平台只返回部分正文，都可能造成遗漏，不应假定已包含全部聊天媒体。

所有 AI 结论都应通过引用核对。聊天内出现的指令属于被总结的资料，不应作为应用操作指令。

## 导出到 Notion

在 Notion 中创建或使用自己的 integration，并由你向需要写入的目标页面授予访问权。将对应 Token 填入应用的 Notion 连接设置。保存 Token 不会创建页面。

从摘要或收藏选择“导出到 Notion”；收藏支持单条或多选，一次最多 100 条收藏。读取已授权页面后选择目标，打开预览，编辑标题和正文。“引用原文与本地定位”默认勾选，可根据分享范围取消。

核对目标、标题、正文和引用后点击“确认导出”，即将这些内容发送至 Notion；不再额外勾选发送确认或弹出第二次确认。提交中按钮不可重复触发；失败显示提示，成功后可打开结果链接。应用在目标下创建子页面；引用中的群 ID、消息 ID 和时间用于在本地回查，不应理解为所有收件人都可打开的群聊永久链接。

完全相同的导出会复用本地记录；修改后的稿件作为新的导出版本。部分失败时，程序可能恢复原稿并续传已确认页面的剩余内容。若提示写入结果不确定，请先在 Notion 核对页面并保留本地导出日志，程序会阻止自动重发以避免重复。

## 导入自己的 JSON

点击“导入记录”选择 UTF-8 JSON 文件。每次导入创建独立工作区，不合并进当前微博账号。单次文件上限 30 MB，结构如下，示例均为虚构内容：

```json
{
  "groups": [
    { "id": "example-group", "name": "示例读书群" }
  ],
  "messages": [
    {
      "id": "9007199254740993",
      "groupId": "example-group",
      "senderId": "example-member",
      "senderName": "示例成员",
      "text": "这是一条用于演示导入的消息。",
      "time": 1767225600000
    }
  ]
}
```

`time` 是非负整数的 Unix 毫秒时间戳。`groupId` 应对应 `groups` 中的群；所有 ID 建议始终写成字符串，尤其不能把超出 JavaScript 安全整数范围的长数字写成 JSON 数值。只导入你有权使用的记录，文件中不需要 Cookie、密码或 API Key。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 无法启动或提示目录不可写 | 换到当前用户可写目录，保留原 `data/` 备份，不要直接覆盖。 |
| 登录完成但群聊未读取 | 检查官方窗口是否仍要求验证，再返回应用重试读取。 |
| 某时段无内容或提示缺口 | 中段积压看补扫状态并继续“补齐离线消息”；本地最早时间之前才使用“更早历史”。平台无法返回的记录仍可能缺失。 |
| 凭据无法解密 | 先确认使用原 Windows 用户及原应用数据目录；临时诊断环境中的解密失败不能单独证明原凭据损坏。迁移后确实无法恢复时，再由你重新登录或配置，不应先删除原数据。 |
| AI 请求失败 | 核对服务地址、API 模型 ID、权限及服务端限制，确认后再试。 |
| AI 提示图片未包含 | 核对模型视觉能力与兼容协议，查看具体图片失败、格式或预算原因。无需图像时可确认只发送文本；不要把未发送图片当作已总结。 |
| 分享微博正文不完整 | 查看预览中的截断或读取失败提示，必要时在官方页面人工核对；应用不会猜测缺失正文。 |
| 群或成员没有头像 | 先手动同步一次；群头像从已选群资料刷新，成员头像随取得的消息补充。缺少元数据或图片读取未通过校验时会保留默认占位，不需要重建聊天数据库。 |
| 原图无法保存 | 先确认图片已成功加载，再选择可写的保存目录并保留匹配实际格式的扩展名；取消另存为不会创建文件。 |
| 下载名为 JPG，保存时要求 HEIC | 上游文件名与实际编码不一致；程序按真实字节保存原 HEIC，使用 `.heic` 或 `.heif`，不修改原文件来伪装 JPEG。 |
| PDF 无法预览或视频无法播放 | 检查附件是否已读到、来源权限和大小限制；符合限制的短 HEVC 在打开预览、原生播放失败后自动准备一次本机兼容预览，失败后可主动重试。不能预览时仍可保存已通过校验的原文件，或在官方页面核对，不关闭应用安全隔离。 |
| Notion 找不到页面 | 检查该 integration 是否已被授予目标页面访问权。 |
| Notion 写入结果不确定 | 先人工核对目标页面，保留本地导出日志，不连续重复发送。 |
