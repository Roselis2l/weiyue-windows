# AI 配置与错误排查

本文说明独立模型设置及现有 AI 请求行为，不配置 AI 也能使用本地摘录。复验使用虚构资料和模拟服务；预设地址和公开文档依据不代表真实服务已联调，当前结果见 [1.1.16 更新说明](1.1.16更新说明.md)。

## 添加或编辑自定义模型

在设置页的 AI 卡片点击“添加自定义模型”或“编辑自定义模型”，打开独立的“添加自定义模型”弹窗。按顺序提供 OpenAI、DeepSeek、Kimi、智谱、MiniMax、混元、千问、小米和自定义。选择厂商后填写自己账号可用的模型名称或 API ID；应用不预填或猜测模型，不自动获取模型列表、不测试连接。

预设官方地址只读，同时显示地区和套餐说明。需要国际站、其他地域、工作空间专属域名或不同套餐时，选择“自定义”，从对应控制台明确复制兼容 Chat Completions 的地址。地址、凭据与模型须属于同一服务；各厂商预设及官方依据见 [AI 厂商 API 来源](AI厂商API来源.md)。

API Key 默认以密码形式输入，眼睛按钮只显示或隐藏本次新输入，不能显示已保存的 Key。原有 Key 只可在厂商和规范化后的实际请求地址均相同时保留；更换模型本身不要求更换 Key。切换厂商或服务地址会清除尚未保存的新 Key，并要求重新输入对应凭据，不能把上一家服务的秘密带到新地址。保存前仍应检查厂商、模型和完整目标。

旧版本没有厂商字段的配置按“自定义”读取，原地址、模型和 Key 保留，启动或打开设置不会重写凭据；用户明确保存后才附加厂商与地址的绑定信息。即使旧地址与某预设相同，从“自定义”改选该厂商仍属于厂商变化，需要重新输入 Key。

点击“返回设置”、关闭按钮或 Escape 会回到外层设置；成功保存后也回到外层。AI 与 Notion 分开保存，外层尚未保存的 Notion Token 输入会保留，但保存 AI 不提交它，单独保存 Notion 也不改 AI 配置。打开或保存这些设置都不会发送聊天。

## 填写正确的服务地址和模型

| 项目 | 官方 OpenAI 示例 | 第三方兼容服务 |
| --- | --- | --- |
| 服务地址 | `https://api.openai.com/v1`，最终请求为 `https://api.openai.com/v1/chat/completions` | 填该服务文档给出的 Chat Completions 基址或完整地址 |
| 模型 | 使用 API ID，例如 `gpt-6-astra` | 使用服务方给出的模型标识，不假定等于官方显示名 |
| Key | 用户本人的 API 凭据，仅在本机设置中保存 | 使用该服务的凭据，不借用其他应用的 Key |

地址可以是 HTTPS 服务根地址、`/v1` 基址或完整 `/chat/completions`。只允许精确 `localhost`、`127.0.0.1`、`[::1]` 使用 HTTP；地址不能带用户名、密码、查询串或片段。明显的 `/responses`、`/messages`、旧 `/completions` 属于不同协议，会在发送前拒绝，不自动替换为另一种 API。

对于精确官方来源 `https://api.openai.com`，1.1.5 兼容已知显示名 `GPT-6 Astra`，发送时解析为同一模型 `gpt-6-astra`，原始设置不改写；其他未知带空格的官方显示名需改填正确 API ID。第三方服务不执行此官方别名转换。官方 API ID 可在 [模型页面](https://developers.openai.com/api/docs/models/gpt-6-astra) 核对。

## 确认实际发送内容和预算

生成前查看原生确认框中的最终 URL、实际模型 ID、每段 4,096 token 预算、时段、消息数与分段数。发送内容包括所选消息的成员名、时间及文字；Key 仅作认证，不进入摘要。发现目标地址或模型不符合预期时取消，先在设置中更正。取消不会发送该次 AI 请求。

1.1.7 点击应用内确认发送后立即关闭应用弹窗，进度与错误移到主标题下；仍须完成原生确认。运行中禁用重复 AI 入口，失败保留错误、不自动重试。成功后主动点击“查看摘要”，不自动跳离阅读页；具体测试状态见 [1.1.7 更新说明](1.1.7更新说明.md)。

官方 OpenAI 请求使用 `max_completion_tokens: 4096`，不带固定 `temperature`。1.1.7 对精确 Kimi 官方来源 `https://api.moonshot.cn` 和 `https://api.moonshot.ai` 也省略固定 `temperature`，保留 `max_tokens: 4096`，避免覆盖模型固定采样要求；依据见 [Kimi 模型参数](https://platform.kimi.com/docs/api/models-overview)。其他兼容服务保持原 `temperature: 0.2`、`max_tokens: 4096` 参数方式，预设地址不代表所有模型参数已验证。

OpenAI 预算同时包括可见输出和推理 token，因此不保证一定返回 4,096 个可见 token。输入另外计量，多段会分别请求，不是固定金额或总费用上限。依据见 [Chat Completions 参数说明](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

若一段达到输出限制，应用停止并提示缩小时段，不自动加预算、切模型或重试；不要把不完整段落当成完整摘要。生成前可减少所选时段或消息范围，但不需要为了开发验证提供新 Key 或授权。

## 按提示排查

| 看到的情况 | 先核对什么 |
| --- | --- |
| 地址格式或协议不支持 | 使用 Chat Completions 基址或完整地址，勿填 Responses、Messages 或旧 Completions 端点 |
| 模型或模型权限提示 | API ID 拼写、该账号是否有模型访问权限；不凭显示名猜 ID，也不自动换模型 |
| 参数或预算提示 | 服务实际要求的字段；官方请求和第三方兼容请求规则不同 |
| 认证或权限提示 | 在用户自己的服务后台核对凭据和权限；不要把 Key 发进聊天或截图 |
| 额度或限流提示 | 服务端剩余额度、用量和限制；应用不会连续自动重试或提高预算 |
| HTTP 400，但没有更具体分类 | 现有安全字段不足以确定原因；先检查地址、API ID 和参数，不能只凭 400 认定 Key 错误或模型故障 |
| 超时、中断或服务端错误 | 请求可能已处理；先查看服务端用量及结果，再决定是否自行重试 |

错误分类最多读取 16 KiB 响应并等待 2 秒，只接受白名单 `code`/`param` 信息。原始错误文本、响应正文和响应头可能含聊天或凭据回显，应用不展示、不记录它们。超限、格式不符或无法归类时只保留安全通用提示。

## 服务联调边界

不能仅凭 HTTP 400 推断唯一原因。兼容处理不代表真实 Key、模型权限、额度和网络已经验证；需要用户配置并明确确认调用。开发保持模拟，本次状态见 [1.1.16 更新说明](1.1.16更新说明.md)。
